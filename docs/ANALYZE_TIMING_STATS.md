# analyze_timing_stats.py - Documentation

## Overview

`analyze_timing_stats.py` is a statistical analysis tool that processes RCCL benchmark timing data to generate comprehensive performance statistics. It aggregates individual GPU kernel execution times across all MPI ranks and correlates them with benchmark wall-clock measurements.

**Location:** `/work/lmeadows/rccl/scripts/analyze_timing_stats.py`

**Version:** 1.0

**Author:** RCCL Performance Analysis Team

---

## Purpose

The script serves as the **first analysis step** in the RCCL performance analysis pipeline:

1. **Aggregate** individual kernel timings from all ranks
2. **Calculate** statistical measures (mean, std, percentiles, CV)
3. **Correlate** GPU kernel times with CPU wall-clock times
4. **Export** results to CSV for downstream analysis

## Input Requirements

### Directory Structure

The script expects a run directory created by `run_timing_sweep.py`:

```
/work/lmeadows/rccl/data/<hostname>/run_{benchmark}_{YYYYMMDD_HHMMSS}/
├── {benchmark}_rank0.csv              # Kernel timings from rank 0
├── {benchmark}_rank1.csv              # Kernel timings from rank 1
├── ...
├── {benchmark}_rank7.csv              # Kernel timings from rank 7
├── {benchmark}_benchmark_output.txt   # Wall-clock times
├── run_metadata.json                  # Run metadata
└── sweep_summary.txt                  # Human-readable summary
```

### Input File Formats

#### Timing CSV Files (`*_rank*.csv`)

Generated by the benchmark's `--save_individual_timings` flag.

**Columns:**
- `iteration` - Iteration number (0 to N-1)
- `time_seconds` - Kernel execution time (seconds)
- `size_bytes` - Message size (bytes)
- `count` - Element count
- `type` - Data type (e.g., "float")
- `op` - Operation (e.g., "sum")
- `root` - Root rank (-1 for collectives)
- `inplace` - In-place flag (0 or 1)
- `rank` - MPI rank
- `total_ranks` - Total number of ranks
- `ngpus_per_rank` - GPUs per rank

**Example:**
```csv
iteration,time_seconds,size_bytes,count,type,op,root,inplace,rank,total_ranks,ngpus_per_rank
0,0.000045123,1024,256,float,sum,-1,0,0,8,1
1,0.000043567,1024,256,float,sum,-1,0,0,8,1
```

#### Benchmark Output (`*_benchmark_output.txt`)

Raw stdout from the benchmark executable.

**Format:**
```
#       size         count      type   redop    root     time   algbw   busbw #wrong
#        (B)    (elements)                               (us)  (GB/s)  (GB/s)
        1024           256     float     sum      -1    37.15    0.03    0.05      0
        2048           512     float     sum      -1    38.42    0.05    0.09      0
```

## Functions

### Data Loading Functions

#### `load_timing_data(output_dir)`

Loads and combines all timing CSV files from a run directory.

**Parameters:**
- `output_dir` (str): Path to run directory

**Returns:**
- `pd.DataFrame`: Combined timing data from all ranks, or `None` if no files found

**Process:**
1. Searches for files matching `*_rank*.csv`
2. Loads each CSV into a pandas DataFrame
3. Concatenates all DataFrames
4. Returns combined data

**Example:**
```python
timing_df = load_timing_data("/work/lmeadows/rccl/data/host/run_all_reduce_20251104_165031")
# Returns DataFrame with ~22,400 rows (8 ranks × 50 iterations × 28 sizes × 2 operations)
```

---

#### `load_benchmark_output(output_dir, benchmark_name)`

Loads the raw benchmark output text file.

**Parameters:**
- `output_dir` (str): Path to run directory
- `benchmark_name` (str): Benchmark name (e.g., "all_reduce")

**Returns:**
- `str`: Raw file content, or `None` if file not found

**Example:**
```python
content = load_benchmark_output(output_dir, "all_reduce")
# Returns multi-line string with benchmark output
```

---

#### `parse_benchmark_output(content)`

Parses benchmark output to extract wall-clock timing data.

**Parameters:**
- `content` (str): Raw benchmark output

**Returns:**
- `pd.DataFrame`: Parsed timing data with columns: size_bytes, count, data_type, operation, root, wall_time_us, alg_bw_gbs, bus_bw_gbs, errors

**Regex Pattern:**
```python
r'^\s*(\d+)\s+(\d+)\s+(\w+)\s+(\w+)\s+(-?\d+)\s+([\d.]+)\s+([\d.]+)\s+([\d.]+)\s+(\d+)'
```

**Example:**
```python
benchmark_df = parse_benchmark_output(content)
# Returns DataFrame with 28 rows (one per size tested)
```

### Statistical Analysis Functions

#### `create_statistical_summary(timing_df, benchmark_df=None)`

Generates comprehensive statistics for each size/operation combination.

**Parameters:**
- `timing_df` (pd.DataFrame): Individual kernel timings
- `benchmark_df` (pd.DataFrame, optional): Wall-clock timings

**Returns:**
- `pd.DataFrame`: Statistical summary with one row per size/operation

**Process:**
1. Groups data by `inplace` flag (0 or 1)
2. For each size within each group:
   - Converts times to microseconds
   - Calculates mean, std, min, max
   - Computes percentiles (P25, P50, P75, P95, P99)
   - Calculates CV = (std / mean) × 100%
   - Matches with wall-clock time from benchmark output
3. Returns sorted DataFrame

**Statistics Calculated:**

| Statistic | Formula | Interpretation |
|-----------|---------|----------------|
| Mean | Σx / n | Average performance |
| Std | √(Σ(x-μ)² / n) | Variability |
| Min | min(x) | Best case |
| Max | max(x) | Worst case |
| P50 | 50th percentile | Median (robust to outliers) |
| P95 | 95th percentile | Tail latency |
| P99 | 99th percentile | Extreme outliers |
| CV | (std/mean)×100% | Relative variability |

**Example:**
```python
summary_df = create_statistical_summary(timing_df, benchmark_df)
# Returns DataFrame with 56 rows (28 sizes × 2 operations)
```

## Statistical Measures Explained

### Mean (μ)
Average kernel execution time across all samples.
- **Use:** Overall performance indicator
- **Limitation:** Sensitive to outliers

### Standard Deviation (σ)
Measure of variability around the mean.
- **Use:** Quantifies consistency
- **Interpretation:** Lower is better (more consistent)

### Coefficient of Variation (CV)
Normalized measure of variability: CV = (σ / μ) × 100%
- **Use:** Compare variability across different sizes
- **Interpretation:**
  - CV < 10%: Very consistent
  - CV 10-20%: Moderate variability
  - CV > 20%: High variability

### Percentiles
Values below which a percentage of data falls.
- **P25:** 25% of samples are faster
- **P50 (Median):** 50% of samples are faster (robust central tendency)
- **P75:** 75% of samples are faster
- **P95:** 95% of samples are faster (tail latency)
- **P99:** 99% of samples are faster (extreme outliers)

**Use Cases:**
- P50: Typical performance
- P95/P99: Worst-case scenarios for SLA guarantees

## Sample Size Calculation

For a benchmark run with:
- **8 MPI ranks**
- **50 iterations per size**
- **2 operations** (in-place, out-of-place)

**Samples per size/operation:**
```
8 ranks × 50 iterations = 400 samples
```

**Total samples for 28 sizes:**
```
28 sizes × 2 operations × 400 samples = 22,400 total measurements
```

This large sample size ensures:
- **Statistical significance:** Reliable mean/std estimates
- **Outlier detection:** P95/P99 capture tail behavior
- **Rank variability:** Captures inter-rank performance differences

## Wall-Clock Correlation

### Purpose
Compare GPU kernel execution time with end-to-end wall-clock time to identify overhead sources.

### Correlation Logic

1. **Exact Match:** If benchmark output has the same size, use that wall time
2. **Approximate Match:** If no exact match, find closest size within 10%
3. **No Match:** Leave wall time as NaN

### Interpretation

| Scenario | Interpretation |
|----------|----------------|
| Wall ≈ Kernel Mean | Minimal overhead, GPU-bound |
| Wall > Kernel Mean | CPU overhead, synchronization, or data transfer |
| Wall < Kernel Mean | Impossible (indicates measurement error) |
| Wall >> Kernel Mean (large sizes) | Pipelining/overlap (expected for large messages) |

**Example:**
```
Size: 1 MiB
Kernel Mean: 35.2 μs
Wall Time: 38.5 μs
Overhead: 3.3 μs (9.4%)
```

### Missing Files

**Cause:** No `*_rank*.csv` files in directory  
**Solution:** Verify `run_timing_sweep.py` completed successfully

### Parse Errors
```
Warning: Failed to parse timing line: <line>
```
**Cause:** Unexpected benchmark output format  
**Solution:** Check benchmark output file for corruption

### Empty Results
```
No statistical summary could be generated
```
**Cause:** No valid timing data after filtering  
**Solution:** Check CSV files for valid data

## Performance Considerations

### Memory Usage
- **Per-rank CSV:** ~50 KB (50 iterations × 28 sizes × 2 ops)
- **Combined DataFrame:** ~400 KB (8 ranks)
- **Peak memory:** < 10 MB (includes pandas overhead)

### Execution Time
- **Typical:** 1-2 seconds for 8 ranks, 28 sizes
- **Dominated by:** CSV I/O and pandas operations

### Scalability
- **Tested:** Up to 64 ranks, 100 iterations
- **Bottleneck:** CSV loading (linear with rank count)

## Troubleshooting

### Issue: "Cannot find timestamp pattern in directory name"

**Cause:** Directory name doesn't match expected format

**Expected:** `run_{benchmark}_{YYYYMMDD_HHMMSS}`

**Solution:** Ensure directory was created by `run_timing_sweep.py`

---

### Issue: Parsed 0 timing entries from benchmark output

**Cause:** Benchmark output format changed or file is empty

**Solution:**
1. Check if `{benchmark}_benchmark_output.txt` exists
2. Verify file contains timing lines (not just headers)
3. Check for "Parsed 0 size results" in `run_timing_sweep.py` output

---

### Issue: Wall time missing for some sizes

**Cause:** Benchmark output doesn't include all sizes (e.g., zero-size filtering)

**Effect:** CSV will have NaN for `wall_time_us`

**Solution:** This is expected for affected benchmarks with alignment issues

### Example 3: Extract Key Metrics with Python

```python
import pandas as pd

# Load analysis results
df = pd.read_csv("run_all_reduce_20251104_165031/all_reduce_timing_analysis.csv")

# Filter out-of-place operations
oop = df[df['operation'] == 'out-of-place']

# Find size with highest CV (most variable)

print(f"Most variable size: {max_cv_row['size_bytes']} bytes, CV={max_cv_row['kernel_cv_percent']:.1f}%")

# Find size with largest wall-kernel gap
oop['overhead_us'] = oop['wall_time_us'] - oop['kernel_mean_us']
max_overhead_row = oop.loc[oop['overhead_us'].idxmax()]
print(f"Largest overhead: {max_overhead_row['size_bytes']} bytes, {max_overhead_row['overhead_us']:.1f} μs")
```
